# K230 视觉子机脚本

第五题用：摄像头拍示波器屏幕 → 判断当前是斜线 / 圆 / 倒 8 → 通过 UART 指挥 STM32 扫频与锁相。
真正的相位闭环仍在 STM32 侧，这里只做「看」和「下指令」。

主控侧的协议实现见 [`Core/Src/vision_slave.c`](../Core/Src/vision_slave.c)，
完整协议说明见 [`docs/vision-protocol.md`](../docs/vision-protocol.md)。

---

## 1. 运行环境

| 项 | 要求 |
|---|---|
| 硬件 | 嘉楠 CanMV K230 + GC2093 摄像头（MIPI-CSI） |
| 固件 | CanMV 官方固件（MicroPython 环境，需带 `machine.UART` / `FPIOA` / `sensor`） |
| 屏幕 | 板载 MIPI 屏可选，用于显示 `Q1/Q2/Q3` 与识别状态 |
| 运行方式 | CanMV IDE 直接运行，或放 SD 卡开机自启 |

---

## 2. 为什么是单文件

CanMV 的 IDE 以「当前打开的单个脚本」为运行单元，`import` 自定义模块要额外处理
文件路径，现场很容易出问题。所以把 5 个模块拼成一个 `main.py`（2143 行），
用注释分隔——**改代码时按分隔行定位，不要被单文件误导成一个大函数**：

| 行范围 | 原模块 | 职责 |
|---|---|---|
| 1–184 | `config.py` | 全部可调参数：串口、判据阈值、扫描范围、超时 |
| 185–556 | `vision_math.py` | 几何计算：长短轴、相位差、对称性、中心凹陷 |
| 557–1146 | `scope_camera.py` | 摄像头采集与屏幕区域提取、图像预处理 |
| 1147–1288 | `sweep_uart_link.py` | UART 协议封装，含序号、应答等待、超时重发 |
| 1289–2143 | `sweep_hold_test.py` | 三个小问的扫描策略与主流程 |

调参只改第一段，逻辑改动在后面四段。

## 3. 版本演进

赛前两周一共迭代了 16 个版本，最终落地的是 6.1。留这个表是为了说明**每个版本在解决什么**——
比留下一堆 `main1.py ... main16.py` 有用得多。

| 版本 | 关键变化 |
|---|---|
| 4.6 | 模糊单点判据，先让整条链路能跑通 |
| 4.7 | 加细扫，粗扫命中后小步逼近 |
| 4.8 | 局部精修，缩小扫描步长 |
| 4.9 | 目标锁定：命中后停止扫描并保持 |
| 5.0 | 斜线判据收紧，减少把椭圆误判成斜线 |
| 5.1 | 命中即停，不再继续扫（原来会扫过头） |
| 5.2 | 强制相位新鲜的严格锁定 |
| 5.3 | 三个小问按 Q1→Q2→Q3 顺序执行，屏幕显示频率 |
| 5.4 | UART 稳定性修复，相位固定下发 |
| 5.5 | 斜线判据优先队列，避免多峰干扰 |
| 5.6 | 斜线谷值锁定 |
| 5.7 | Q2/Q3 复用 Q1 测得的频率，不再各自全范围扫 |
| 5.8 | 频率稳定后按键切换小问 |
| 5.9 | 斜坡保持 + 按键切换 |
| 6.0 | 真实目标门限（按示波器实际波形定的阈值） |
| **6.1** | **倒 8 先二倍频再扫，Q3 不再被 Q2 的结果带偏** |

从 5.7 开始有个关键转变：**Q2 和 Q3 不再独立全范围扫频**，而是严格用 Q1 保下来的 `f` 和 `2f`。
原因是全范围扫三个小问每次要几十秒，而题面要求控制时间 ≤10 s。
先测准 f，后面两个小问直接在已知点上微调，才能压进时限。

## 4. 三个小问怎么判

| 小问 | 目标 | 主要判据（`config.py` 段） |
|---|---|---|
| Q1 斜线 | 8×8 div 对角线 | 长短轴比 ≤ 0.45 |
| Q2 圆/椭圆 | 直径 8 div 的圆 | 长短轴比 ≥ 0.84、相位差 ≥ 80°、椭圆拟合残差 ≤ 0.23 |
| Q3 倒 8 | 上下对称的 ∞ | 长短轴比 ≥ 0.94、对称误差 ≤ 0.15、腰部中心凹陷 0.045~0.14、水平穿越 ≥ 3 次 |

完整阈值表与单位见 [`docs/vision-protocol.md`](../docs/vision-protocol.md) 第 7 节。

**注意 Q1 与 Q3 的阈值几乎互补**（0.45 与 0.94），中间 0.45~0.94 是「还没调好」的过渡区，
两边都不认。这是刻意的：宁可多扫一会儿，也不要把半成型的图形判成完成。

## 5. 怎么跑起来

1. **烧固件**：K230 刷 CanMV 官方固件，确认 IDE 能连上。
2. **放脚本**：把 `main.py` 拷到 SD 卡根目录（或 IDE 里直接打开运行）。
3. **接串口**：`GPIO50 → STM32 PB11`、`GPIO51 → STM32 PB10`、**必须共地**。
4. **对准屏幕**：摄像头对准示波器屏幕，按赛题要求挡住面板其余部分。
5. **上电顺序**：两块板都上电即可，谁先都行（握手机制有兜底）。
6. **验证版本**：串口上必须同时看到两边版本号——
   `$K230_READY,F5_VISUAL_PLL_6.1_...` 与 `$STM32_READY,F5_FFT_OU_SLAVE_1.4_...`。
   少一个就说明有一块板在跑旧程序。
7. **操作**：STM32 上按 PA0 进视觉模式，然后按 PD12 / PD13 / PD3 依次跑 Q1 / Q2 / Q3。

三个小问必须按顺序：Q2 和 Q3 依赖 Q1 测出的频率。

---

## 6. 已知限制

- **依赖实验室照度**：示波器屏幕在强环境光下对比度不足，识别会抖。赛题允许用挡板遮挡，建议一直挡上。
- **不做幅度闭环**：只读屏幕上的图形形状，不测峰峰值。第 4 题的幅度档位仍由 PB4~PB7 硬件选通。
- **60 秒封顶**：单小问超过 `LOCK_DEADLINE_MS` 判失败，避免卡死在扫描里。
- **单文件 2143 行**：改起来不如多文件舒服，但换来现场部署简单，这个取舍是刻意的。
